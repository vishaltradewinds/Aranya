# ARANYA N2N and Real-Work Journeys

## Purpose

This document defines the first implementation contract for the reconciled ARANYA experience.

## N2N

ARANYA operates as a Network-to-Network layer:

**Network A ↔ ARANYA ↔ Network B**

A network may be a community, FPO/FPC, SHG, cooperative, VDVK, processor network, buyer network, research network, logistics network, finance network, certification network or institutional network.

ARANYA does not need to own the network. It connects legitimate networks while preserving network identity, permissions, provenance and authority.

## Journey model

Every stakeholder starts from a real intent:

- I HAVE
- I NEED
- I CAN
- I WANT TO CONNECT

ARANYA resolves the intent into a context-aware journey and exposes only the next useful action.

Core lifecycle:

**INTENT → JOURNEY → ACTION → EVIDENCE → VERIFICATION → OUTPUT → VALUE → SETTLEMENT → OUTCOME**

## Authority-aware walking

A journey is constrained by stakeholder role, legitimate authority, jurisdiction, resource context and applicable rules. ARANYA may guide and orchestrate; it does not grant authority that the actor does not possess.

## Output and payment

The platform must distinguish:

- reported/claimed activity
- captured evidence
- verified output
- counterparty acceptance
- payable value
- actual settlement

The app never pays merely for clicks, time spent or artificial points. Payment requires a legitimate value/contractual/programmatic basis.

## Onboarding

The primary scaling strategy is **network-first onboarding**. A network can introduce its members, resources, capabilities and needs progressively. Individual identity and control remain with the individual/stakeholder.

## UX

The first screen should feel like entering ARANYA, not opening an ERP:

**“Batao. Aaj kya karna hai?”**

The user can speak, type, show a photo or choose a simple intent. The system then reveals one next step.

## Non-goals

- social-media mechanics
- popularity rankings
- unnecessary gamification
- artificial upgrade pressure
- duplicate reporting
- replacing statutory authorities
