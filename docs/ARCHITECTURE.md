# ARANYA Architecture

## Product shape

ARANYA is the **digital jungle** of the real-world nature-based economy. The user experience is a walk through real work, not navigation through an administrative application.

## Common operating core

Identity → Authority/Context → Intent → Journey → Action → Evidence → Rules → Network Match → Handover/Transaction → Output → Settlement → Audit

## Network-to-Network layer

**Network A ↔ ARANYA ↔ Network B**

Networks remain independently owned and governed. ARANYA provides interoperable discovery, identity/context, permissions, evidence, workflow and transaction connectivity.

## Stakeholder paths

- Producer / forest-dependent person
- Tribal/community stakeholder
- Community / FPO / FPC / SHG / cooperative
- Aggregator / collection centre / VDVK
- Processor / manufacturer
- Buyer / industry / exporter
- Transporter / warehouse / depot
- Research / technology / training
- Testing / certification
- Finance / insurance
- Authorised government users
- Platform administrator
- Consumer where appropriate

The same underlying ecosystem is presented differently according to legitimate role, authority, jurisdiction, context and task.

## AI layer

AI is an interpretation and orchestration layer for natural language, voice, local terminology, images, documents and intent. It can recommend next actions and identify potentially relevant stakeholders or requirements, but cannot create statutory authority or convert an unverified claim into truth.

## Real-work/output layer

A journey records the real activity around a task. Evidence states remain distinct:

**CLAIMED → EVIDENCED → VERIFIED → ACCEPTED → PAYABLE → PAID**

Payment is not generated merely by app activity; it follows a legitimate value/contractual/settlement basis.

## Experience rules

1. Show the next useful step, not the whole system.
2. Capture evidence during work; avoid duplicate reporting.
3. Voice/photo/local-language/assisted/offline pathways are first-class.
4. A completed real-world outcome is the primary success signal.
5. Regulatory and institutional authority remains attributable and scoped.

## Existing foundation retained

The current backend already provides identity/RBAC, evidence/provenance, lifecycle/state transitions, regulatory rules, persistence and audit foundations. New journey/N2N capabilities must extend these foundations rather than replace them.

## First implementation focus

Madhya Pradesh remains a controlled validation environment, not the conceptual center. The first complete physical journey should validate the common operating model before national expansion.
